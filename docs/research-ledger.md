## 避けたい失敗（前 Atlas K01–K20）との関係

- K01 チャットで全部決めて最終 plot だけ返す → 意図・候補・知識・版を型付きで残しているので避けている
- K06 警告を消すまで AI が自動修正 → 悪い run も残し、原因を人と話す流れにした（v1 の例）
- K07 気に入った予測世界だけ残す → 判定は知識として残すだけで、世界を間引かない
- K12 AI の長い説明を監査記録とみなす → 監査は版・知識・run の結びつきで行い、説明文には頼らない
- K17 pixel と自然言語だけを agent へ公開 → 世界は ID と数値で、指した対象は model 単位で渡す
- K14 すべての変更に人の確認 → 表示と知識には確認を求めず、モデルの変更だけ採用を求めている
- K13 毎回まったく違う画面 → 2 例とも同じ文法。ただし生成 UI がないので、まだ試されていない

## 検証の記録：関数形の違和感（v3 → v4）

- データだけでは形を言えなかった。試験機 C の記録は区間あたり 4〜8 点で、区間ごとの事後予測チェックでは外れが 1 区間（207–253°C）、問題のない試験機 A にも偶然の外れ（67–113°C, P = 0.01）が出た
- 形の知識は人から入った。形のレンズでモデルのばらつき（20°C から直線で増える）の上に「150°C まで平ら、そこから増える」をなぞり、「ヒーターが 150°C で入る機種」と送った
- Claude が 3 つの関数形（揺れ始めを推定する折れ線・150°C 固定の折れ線・なめらかな加速）を返し、1 つ目を採用。差分は T_onset の追加と recorded のばらつきの式の 2 行だけ
- v4（Stan）: 試験機 C の上乗せは 100°C で 0.0（v3 は 7.1、真 0）、300°C で 30.0 [21.5, 43.1]（v3 は 24.9 [17.3, 33.6] で真の 40 を外していた）。揺れ始めは 144.6 [123, 163]（真 150）
- ただし揺れ始めの温度の縮みは 32%。形の大部分は人の知識が決め、データは少し後押ししただけ。レンズはそれを隠さない

## 検証の記録：裏で育つ事後分布（v5〜v7）

- 版を採用すると、サーバーが自分で近似 → NUTS を計算する（Claude に頼まない）。v7 では 21 秒でコンパイル、25 秒で Pathfinder、34 秒で短い NUTS、75 秒で NUTS が届いた
- Pathfinder はこの階層モデルで局所解に落ちた（20°C の強度 2.4、試験機の偏り約 500）。最初は気づかず「事後分布」として表示していた。Pareto k（2.7〜4.7）を読むようにし、0.7 を超えたら表示に使わず、短い NUTS を自動で挟むようにした（F21）
- NUTS 段階での再コンパイル（約 20 秒）を、モデルファイルを書き直さないことでなくした
- テストが、版の切り替え時に新しい版のジョブが二重に走るバグを見つけた
- 同じ版・同じデータの NUTS は、サーバーを再起動しても同じ値になる

## 検証の記録：Stan から NumPyro へ（2026-10-08）

- Stan は版ごとのコンパイル（20〜40 秒）がいちばん頻繁な操作に乗り、Windows での導入も脆かった。裏の計算は常駐の NumPyro ワーカーに移し、Stan は手動の最終確認用に残した
- ラプラス近似は、試料ごとの潜在変数があるモデルでは原理的に使えなかった。結合事後分布の最頻値が「測定誤差 → 0」に崩れる（Adam でやり切ると測定誤差 0.11、個体差 67）。潜在変数のないモデル（曲線）では BFGS 1 回でラプラス近似が NUTS とほぼ一致（Pareto k 0.54）
- 潜在変数のあるモデルでは平均場 ADVI を使うが、v3・v7 では Pareto k 1.33・0.99 で信用できず、検査がそれを止めた。中身も強度 454（NUTS 500）、測定誤差 10（NUTS 3）とずれていた
- 途中のつまずき：SVI の損失は「更新前」の値なので、BFGS が動いていないと読み違えた。ラプラスのガイドを直接呼ぶと最頻値の一点しか返さず、区間が潰れた。平均場の密度を次元方向に合計し忘れていた
- 次の候補：潜在変数を積分で消してから近似する INLA 型の入れ子ラプラス（この種のモデルで速くて信用できる近似になりうる）

## 検証の記録：推論のエンジン（2026-10-08）

- 題材は観測過程・繰り返し測定つきの版（試料 80・試験機 3・記録 100、打ち切り 1）。NUTS は 19 秒・ESS 130・発散 17
- Claude がこの版専用に崩壊型 NUTS を書いた。試料の真の強度と試験機のずれ（どちらも正規の潜在層）を解析的に積分し、9 個の超パラメータと打ち切り記録の補完変数だけを NUTS で動かす。周辺尤度は Woodbury 恒等式と試験機の数の Schur 補行列で記録数に比例する計算。消した量は条件付き正規分布から同時に引き直す。5〜7 秒・ESS 1336・発散 1（1 秒あたり ESS で 30 倍）。実データで NUTS と目立ったずれなし
- 素朴だけれどパラメータの多い場合（同じモデルで試料 500・試験機 10・記録 750、潜在変数 510 個）では、NUTS が 39 秒で R̂ 1.045・ESS 58・発散 45（収束していない）、崩壊型が 32 秒で R̂ 1.003・ESS 2798・発散 0。規模が大きいほど専用のアルゴリズムの差が開く
- 較正（SBC、40 組 × 21 量）で偏りは検出されず。わざと誤りを入れて検出力を確かめた：行列式の 1 項落ちは検出（tau_bias の真値が 32/40 組で全 draw より下）、試験機のずれのシャッフル（周辺は正確）は潜在値の和だけが検出、条件付き独立の引き直し（相関 −0.88 → −0.81）は検出されず。40 組の検出力には限界がある
- 最初の較正は周辺の量だけを見ており、codex の引き継ぎ（相関を壊す誤りは周辺の検査を通る）を受けて、実際の記録が指す試料と試験機の組の和を加えた。カイ二乗だけでは山型・谷型への検出力が弱く、順位の位置と広がりの検定を足した
