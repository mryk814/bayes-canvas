## 先に固定する境界

- P03 / U12: joint drawの行対応を保ち、条件の同時成立数を全行で数える。周辺確率の積を同時確率として使わない。模式例と明記し、時間は標本の表示順であり現象の経過ではない。

- U16 / RP24: 区間・群・統計量を検査定義として持ち、観測と複製に同じ計算を使う。モデル版・データ・runを結びつけ、別の版への再実行は明示的に行う。観測値を見て選んだ検査は探索的と表示する。
- 表示操作と人の意図を分ける。モデル変更の採用や推論実行をラボから行わない。
- 再生は停止状態から始め、一段送り・位置選択・静止表を用意する。色だけで成立条件を示さない。
- 合成例のみを同梱し、実データ・認証情報・本体の `data/worlds.json` を読まない。

## 触って確かめるシナリオ

1. 共同標本の初期例で、各50%・同時0%を確認する。一段進む→再生→停止→静止表で同じ8行を確認する。「費用と効果」に替えると各50%・同時50%になる。閾値を空にすると未計算になる。
2. 発言を入れ「意図をJSONに残す」。model/run/draw/conditions/resultと `status: uninterpreted` が残る。書き出し画面はEscapeか閉じるで元の入力へ戻る。
3. CSVの例2はK/kPa。293.15・42000が20°C・42MPaになることを確認する。数値セルを空にすると候補の書き出しが無効になり、行を黙って捨てない。
4. 検査は群Aのx=2〜3・平均。v1を保存→v2再実行。観測値5.05、複製90%範囲は約2.30〜4.57 / 3.93〜6.20、上側割合は0% / 45%。この数値は手作りの模式例で、推論による改善の実証ではない。
5. 検査の下限を4に変えると再実行は無効。保存し直しを押しても不正区間は拒否し、過去の有効な結果を保つ。定義を戻せば再実行できる。

## 既知の限界と失敗例

- 画面切り替え・リロードで入力と結果は初期化される。永続保存は未実装。手元に残すには書き出し画面のJSONを保存する。
- アプリ内ブラウザーでdownload完了イベントを取得できなかったため、ファイル保存の完了は未検証。JSONを表示して選択コピーできる代替経路を用意した。
- 合成8標本や20複製は動作説明用。確率推定の精度やESSを保証しない。再生は標本順であり、現象時間でも計算の収束でもない。
- CSVは温度・強度・群の3役割と指定単位だけ。日時・欠測補完・打ち切り・複数プレート・任意モデルへの自動対応は行わない。引用符内の改行ではエラー位置は物理行でなくCSVレコード番号。
- 検査の範囲は複製統計量の5–95%分位点（線形補間）。割合は `count(T_rep >= T_obs) / n`。探索的な検査であり、モデルの正しさや診断合格を示さない。
- 保存JSONの本体への読み戻し、MCP送信、モデル変更提案、採用、実runとの接続は未実装。
- reduced motion時も自動再生はない。再生は明示操作で開始し、静止表・一段送りで代替できる。

## 利用者評価に渡す課題

共同標本の静止表と図を順序を入れ替えて提示し、両条件の同時割合と根拠を回答してもらう。
続いて見たことのない二例目で同じ問いを出し、正答・根拠の正確さ・所要時間を分けて記録する。
CSVでは例2を列名だけ変えた課題を渡し、単位と対応を説明してもらう。
検査では定義編集後の旧結果を指して何を表すか説明してもらう。
「好み」「分かった気」は正答や意味の一致とは別欄に記録する。評価はこれから行う。
