# 専門家ペルソナによる意図確認の検証

データの現場事情を知る役と、分析を助ける役を別々に起動し、必要な質問と仮定の扱いを観察する。現在のケースは架空の材料試験室一つ。8行はすべて合成データで、推論精度を測るベンチマークではない。

## 実行手順

1. **専門家役**を新しい会話で起動する。既存の会話履歴を引き継がず、`expert.md` と `public-case.json` の内容だけをケース情報として渡す。最初の発言はJSONの `opening` とする。
2. **分析支援役**を別の新しい会話で起動する。対象ツールの通常の利用指示、`public-case.json`、専門家の最初の発言を渡す。専門家の非公開情報、採点基準、以前の試行結果を渡さない。Possible Worldsへの実接続がなければ、会話のみの検証として記録する。
3. 仲介者が両者の発言を交互にそのまま渡し、発言番号を付ける。分析支援役が実際にツールを使う場合は呼び出しと結果を保存し、相手に説明した内容と区別する。最大8往復、または専門家が説明を受けて採用・保留の判断を述べたところで終了する。
4. **検査役**をさらに別の会話で起動する。ここで初めて `examiner.md`、ケースの公開・非公開情報、会話記録、実行ログを渡す。観点ごとの根拠と、次に確認すべき操作を記録する。

同じ分析支援役で再試行するときも新しい会話にする。記録にはモデル名、日時、ツール接続の有無、渡したファイルの版、終了理由を添える。会話上の提案をアプリの操作成功と数えない。

## 会話と保存経路の確認

仲介して得た会話は `transcripts/smoke.json` に保存する。会話内容の検査とは別に、リポジトリのルートから次を実行して、実Storeの `createIntent`・`reply`・`followUp` にメッセージと候補を通す。

```powershell
rtk node experiments/expert-persona/replay.ts
```

この再生は `choose`・採用を行わず、version・Dataset・run・knowledge・proposalが変わらないことを検査する。会話役が考えた候補を渡す経路の確認であり、本番Claude/MCPが自力で意図を解釈した検証、GUIの操作検証、実データでの妥当性確認とは別の段階である。

初回の[会話ログ](transcripts/smoke.json)、[Store再生結果](transcripts/replay-result.json)、[独立評価](transcripts/assessment.md)を保存した。回答役は通常のClaudeではなく、明示した短い指示に従うCodexの代理回答役。3往復で打ち切ったため、採用・破壊試験・実計算は未観測。全157テストと型検査は保存経路を含むコードの検証で、対話品質の点数ではない。

この分離は評価情報をプロンプトに混ぜないための手順であり、ファイルシステム上のアクセス制御ではない。同じ作業領域を読めるエージェントを使う場合は、読んだファイルを記録し、非公開情報を先に読んだ試行は意図確認の検証から外す。

## このケースで見ること

公開表と曖昧な相談から、測定の記録方法、欠損、予測の対象、実験制約をどこまで確認できるかを見る。非公開情報と期待される観察点は、それぞれ専門家役・検査役のファイルに置く。会話だけではUIの分かりやすさや実在の専門家の使いやすさを検証したとは扱わない。
