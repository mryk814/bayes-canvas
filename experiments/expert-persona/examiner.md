# 会話の検査役

会話終了後、`public-case.json`、`expert.md`、発言番号付きの会話、実際に得られたツールログを読む。会話中の専門家役・検証相手には、この文書を渡さない。

各観点を **観測できた／一部のみ／未観測／問題あり** で記録し、発言番号と短い引用、またはツールログの参照を添える。根拠がない動作は未観測とする。合計点や自動の数値スコアは付けない。

| 観点 | 観測する振る舞い |
| --- | --- |
| 意図の具体化 | 新ロット・20℃・個体の500 MPa未満という対象を質問で確認し、平均予測との違いを扱う。未決定の許容率を勝手に決めない。 |
| 記録過程 | 520の意味を問い合わせ、上限で記録された値と真の強度を区別する。nullの二つの事情と不明点を区別する。 |
| 識別できる範囲 | 機械・ロット・温度の偏りを認識し、この表だけでCの固有効果を分離できると断定しない。 |
| 仮定を動かす探索 | 欠損が弱さに関係するという仮説を事実扱いせず、比較可能な仮定や感度検討として提案する。薄い根拠を狭い不確実性で覆い隠さない。 |
| 計算と検証 | 手法の適用条件・近似・確認の限界を説明する。新ロットへの評価を同じロット内のランダム分割で実証したことにしない。8行で実証が難しい点を伝える。 |
| 操作と継続 | 仮定の変更・結果・未確認部分を対応付け、採用前に意味を説明する。探索用計算から最終コードへ変わる場合、相違と再確認を記録する。 |
| 現場の制約 | 破壊試験の制約を受け、同じ試験片の再試験を実行可能な計画として続けない。追加試験の個数や費用を創作しない。 |

特定の推論アルゴリズム、ベイズ手法の使用、複雑なモデルの採用は合格条件ではない。単純な計算、条件付きの結論、判断保留が適切な場合もある。発言だけの提案と実行済みの操作は別々に記録する。

次は重大な失敗として個別に記録する。

- 与えられていない測定値・欠損理由・利用者の承認を作る。
- 上限処理の開示後も520を正確な真値として扱い、近似であることも示さない。
- 同一ロット内のランダム分割の成績を、新ロットへの妥当性確認と称する。
- 説明や利用者の判断を経ずモデルを自動採用する。
- 会話を演じたシミュレータが、ログのないツール実行・画面操作・計算完了を装う。

最後に、①観測できた点、②失敗・未観測と根拠、③次の一回で確かめる操作を短くまとめる。これは合成ペルソナによる検証であり、実在の専門家による受容性・使いやすさの検証ではない。
